# J5 Node Contact Delivery

Date: 2026-10-05  
Status: implemented locally; deployment and live SES test pending

## Deployment change

- Astro uses the official Node adapter in standalone mode. Public pages remain prerendered, while `/api/contact` runs on the server.
- DigitalOcean App Platform must change the `web` component from a static site to a web service.
- Build command: `pnpm install --frozen-lockfile && pnpm build`
- Run command: `pnpm start`
- Recommended size: `apps-s-1vcpu-0.5gb`, one instance.
- Current DigitalOcean price for that size: USD 5 per month, including 50 GiB outbound transfer. The present static-only app can be free, so the expected increase is USD 5 per month before any excess transfer.

## Runtime variables

Set these on the Act AI Studio web service at run time:

- `AWS_ACCESS_KEY_ID`: secret; use the existing SES sending credential.
- `AWS_SECRET_ACCESS_KEY`: secret; use the existing SES sending credential.
- `AWS_SES_REGION`: `eu-west-2`.
- `CONTACT_EMAIL_FROM`: `Act AI Studio <results@advancedanalytica.co.uk>`.
- `CONTACT_EMAIL_TO`: `jonathan@advancedanalytica.co.uk`.

The endpoint also accepts the existing `LEAD_EMAIL_FROM` and `LEAD_EMAIL_TO` names as fallbacks.

## Delivery and privacy

- The sender uses the controlled and SES-verified `advancedanalytica.co.uk` domain.
- SES processes the message in `eu-west-2`. The site keeps no submission database or files and logs no submitted personal data.
- The delivered message is retained in the receiving business mailbox. The privacy notice says this explicitly.
- The server keeps only a salted, non-reversible rate-limit key in process memory for up to 15 minutes.
- A hidden honeypot rejects basic automated submissions. No CAPTCHA or third-party browser script is used.
- The browser shows success only after SES returns a message ID. Provider or network failure displays `hello@actai.studio`.

## DNS

The existing SES identity has an `_amazonses.advancedanalytica.co.uk` verification TXT record. Before production release, confirm the three SES Easy DKIM CNAME records shown for the identity in the AWS SES console. Their selector names are generated by SES and cannot be inferred from the domain.

The root SPF record currently authorises Google only. SES DKIM is sufficient for DMARC alignment when working correctly. If a custom SES MAIL FROM domain is enabled later, publish the exact SES MX and SPF records AWS supplies for that subdomain; do not add a second SPF record at the root.

## Release gate

J5 is not complete until the Node service is deployed with the runtime variables and a real submission receives an SES message ID and arrives in the destination mailbox. No production deployment was made from this branch.
